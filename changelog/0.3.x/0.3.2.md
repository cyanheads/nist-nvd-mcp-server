# 0.3.2 — 2026-10-08

## Changed

- **Numeric and boolean strings are repaired and accepted** for number and boolean arguments (`"limit": "2"`, `"brief": "true"`) instead of rejected (mcp-ts-core 0.13.14).
- **Argument-rejection hints lead with the field path** (`severity: Invalid option: expected one of …`) (mcp-ts-core 0.13.9).
- **Tool and resource error results carry `data.requestId`**, and a tool error's text ends with `request <id>` (mcp-ts-core 0.13.10). Error codes, `data.reason`, and recovery hints are otherwise unchanged.
- **The NVD request debug log record names the endpoint only**, no longer the full request URL with the caller's query values.
- **`server.json` npm entries launch the package with `npx`** with no `run start:*` arguments, and the Streamable HTTP entry sets `MCP_TRANSPORT_TYPE=http` (mcp-ts-core 0.13.11 template).
- **Docker image**: production dependencies install in a `deps` stage on the build platform, so the arm64 image no longer runs Bun under emulation (0.13.10); musl-only packages are pruned from the image (0.13.11); base images move to Bun 1.4.2 (0.13.7).
- Framework resync: `framework-skills/`, `scripts/` (adds `install-otel.ts` and `prune-musl-packages.ts`), `.gitignore`/`.dockerignore` (`.env*` and registry token files), `.mcpbignore` (`logs/`, `.cache/`, `coverage/`, `tests/`), and the CodeQL workflow (one analysis per language).
- Handlers no longer call `ctx.recoveryFor`; the framework fills each declared recovery hint at the tool and resource boundary.
- `.env.example` lists the new framework variables (`MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_LLM_INTERACTIONS`, OTLP per-signal endpoints); `CLAUDE.md`/`AGENTS.md` guidance and README badges updated.

## Fixed

- **Plugins and bundle** (#48): the Claude Code and Codex plugin manifests sent the literal placeholder `your-nvd-api-key` as `NVD_API_KEY`, which NVD rejects, so every call failed until the user edited the file. The key is now an optional user setting — Claude Code `userConfig` (sensitive), Codex `env_vars`, and a new `user_config` option in the `.mcpb` bundle. Left empty, the server runs keyless.
