# 0.1.17 — 2026-07-27

## Changed

- **Empty-page notices on all three paginating tools separate three outcomes** — `nvd_search_cves`, `nvd_search_cpes`, and `nvd_audit_cpe` no longer treat any empty page as an overrun offset. The past-the-end notice now requires `offset >= totalResults`; a valid offset inside a non-zero `totalResults` gets its own notice naming the contradiction (NVD reported matches but returned none) instead of "lower the offset" or "nothing matched," neither of which is true there. ([#34](https://github.com/cyanheads/nist-nvd-mcp-server/issues/34))
- **`nvd_search_cves` and `nvd_audit_cpe` gain the next-page notice `nvd_search_cpes` already had** — a partial page now names the offset that reaches the next one. `nvd_audit_cpe` advances by `returned + filteredCount`, not `offset + returned`: its `returned` count is taken after the client-side `severityMin` filter, while NVD spent an index position on every row it served, so advancing by `returned` alone would re-serve rows the filter had just dropped. ([#36](https://github.com/cyanheads/nist-nvd-mcp-server/issues/36))
- **`nvd_get_cve`'s brief mode calls the service's `toBriefCve()` instead of rebuilding the row inline** — `BriefCveRecordSchema` moved to `src/mcp-server/tools/schemas/brief-cve.ts`, shared by `nvd_search_cves`; `UnfilteredBriefCveRecordSchema` covers `nvd_get_cve`, which has no severity filter and so never emits `filteredSeverity`. The brief output schema declares these fields directly instead of an untyped passthrough object, so a divergence between the two surfaces now fails the typecheck. `CveRecord` and `BriefCveRecord` in `src/services/nvd-cve/types.ts` became `type` aliases to get the implicit index signature that returning them against a passthrough schema needs. ([#35](https://github.com/cyanheads/nist-nvd-mcp-server/issues/35))
