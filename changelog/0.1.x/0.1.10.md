# 0.1.10 — 2026-06-04

## Fixed

- **`nvd_audit_cpe`**: `cpe_not_found` now fires only when `response.totalResults === 0` (CPE absent from NVD). Previously the guard ran after client-side `severityMin` filtering, so a valid CPE with results below the threshold threw a misleading "CPE not found" error. Filtered-to-empty now returns structured success `{ cves: [], totalResults: N, returned: 0 }`. ([#17](https://github.com/cyanheads/nist-nvd-mcp-server/issues/17))
- **`nvd_get_cve_history`**: removed the unconditional `cve_not_found` throw when `changes.length === 0`. Paginating past the end of the history set (and CVEs with no recorded history) now returns structured empty success rather than an error. ([#16](https://github.com/cyanheads/nist-nvd-mcp-server/issues/16))
- **`nvd_audit_cpe` error contract**: updated `cpe_not_found` `when` clause to reflect the tightened guard (`totalResults === 0`, not post-filter empty).
- **`nvd_get_cve_history` error contract**: removed the `cve_not_found` contract entry — the handler no longer throws it; the error is classified downstream if NVD returns HTTP 404.
