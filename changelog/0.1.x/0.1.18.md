# 0.1.18 — 2026-07-31

## Added

- **`nvd_search_cves` gains `exactPhrase`** — forwarded as NVD's valueless `keywordExactMatch` flag, matching `keyword` as a phrase instead of ANDing its words independently. Requires `keyword`; used alone it raises the new `exact_phrase_without_keyword` (`ValidationError`) instead of running the search unmodified. Echoed in `filtersApplied` alongside `keyword`. ([#44](https://github.com/cyanheads/nist-nvd-mcp-server/issues/44))

## Fixed

- **CVSS entries scored `0.0` were dropped** — `extractCvssScores()`'s `baseScore` guard tested falsiness, discarding every metric NVD scores `0.0` along with genuinely missing ones. Now tests for `undefined`. ([#39](https://github.com/cyanheads/nist-nvd-mcp-server/issues/39))
- **CVSS v2 `baseSeverity` was read from the wrong depth** — NVD returns it as a sibling of `cvssData` on `cvssMetricV2` entries, not nested inside it. `RawCvssMetric` gains a top-level `baseSeverity`, and extraction reads it before falling back to score-derived `deriveV2Severity()`, which now only covers a v2 metric that carries no label at either depth and no longer invents a `NONE` tier at `0.0` (NVD labels every `0.0` v2 metric `LOW`). Together with the guard fix, a `severityMin` audit no longer silently drops a `0.0`/`LOW` CVE. ([#39](https://github.com/cyanheads/nist-nvd-mcp-server/issues/39))
- **`nvd_audit_cpe` treated a product with zero CVEs as `cpe_not_found`** — `auditCpe()` threw whenever NVD returned `totalResults === 0` for a `cpeName`, indistinguishable from a genuine typo and reachable immediately after `nvd_search_cpes` had just resolved the same name. Both input arms now return an empty success (`cves: []`, `totalCount: 0`) with a notice naming the CPE string as the one thing still unconfirmed. The now-unreachable `cpe_not_found` error contract entry is removed from `nvd_audit_cpe`. ([#40](https://github.com/cyanheads/nist-nvd-mcp-server/issues/40), resolves [#41](https://github.com/cyanheads/nist-nvd-mcp-server/issues/41))
- **`docs/design.md` documented every validation failure as `InvalidParams`** — the tool summary table and every per-tool error contract block named the pre-0.1.7 error code; the wire has returned `ValidationError` since that release. Documentation-only. ([#43](https://github.com/cyanheads/nist-nvd-mcp-server/issues/43))
