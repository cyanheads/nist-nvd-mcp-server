# 0.1.3 — 2026-05-24

## Fixed

- **`nvd-cve-service`** — CVSS v2 base severity now derived from the numeric score when NVD omits `baseSeverity` (v2 responses never include it). Ranges: 0→NONE, 0.1–3.9→LOW, 4.0–6.9→MEDIUM, 7.0–10.0→HIGH ([#11](https://github.com/cyanheads/nist-nvd-mcp-server/issues/11))
- **`nvd_search_cves`** — invalid date strings now throw `invalid_date_format` with `data.reason` instead of an untyped error ([#9](https://github.com/cyanheads/nist-nvd-mcp-server/issues/9))
- **`nvd_search_cves`** — `severity=CRITICAL` with `severityVersion=v2` now throws `invalid_severity_for_version` locally before hitting NVD; CVSS v2 has no CRITICAL tier ([#13](https://github.com/cyanheads/nist-nvd-mcp-server/issues/13))
- **`nvd_search_cves`** — offset-past-end (returned=0, totalResults>0) now displays an actionable pagination message instead of "No CVEs matched the search criteria" ([#14](https://github.com/cyanheads/nist-nvd-mcp-server/issues/14))
- **`nvd_search_cves`** — description corrected: no-filter queries return CVEs in NVD default index order (oldest-first by CVE ID), not "most recently modified" ([#12](https://github.com/cyanheads/nist-nvd-mcp-server/issues/12))
- **`nvd_search_cpes` / `nvd_audit_cpe`** — malformed CPE strings (not starting with `cpe:2.3:`) now throw `invalid_cpe_format` locally before hitting the API ([#10](https://github.com/cyanheads/nist-nvd-mcp-server/issues/10))

## Changed

- **Tool descriptions** tightened across `nvd_search_cves`, `nvd_search_cpes`, `nvd_audit_cpe`, `nvd_get_cve_history`, and `nvd://cve/{cveId}` — removed redundant language, sharpened guidance
- **Spread patterns** simplified to `&&`-conditional spreads throughout service and tool layers (code simplification pass)
- **`@module` tags** corrected to include `src/` prefix on all definitions
