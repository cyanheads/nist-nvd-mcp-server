# 0.1.7 — 2026-05-28

## Changed

- **Error codes reclassified** — all tool error-contract entries that used `JsonRpcErrorCode.InvalidParams` now use `JsonRpcErrorCode.ValidationError`. Affected: `nvd_search_cves` (6 reasons), `nvd_search_cpes` (2 reasons), `nvd_audit_cpe` (4 reasons), `nvd_get_cve` (1 reason), `nvd_get_cve_history` (1 reason). Clients that branch on `error.code` should expect `-32602` to be replaced by the `ValidationError` code.
- **`nvd-cve-service.ts`** — `McpError(JsonRpcErrorCode.NotFound, …)` replaced with `notFound()` factory calls for the `cve_not_found` and `cpe_not_found` paths. Semantically identical; now consistent with the rest of the codebase.
- **`@cyanheads/mcp-ts-core` ^0.9.9 → ^0.9.13** — picks up:
  - HTTP request-body cap (`MCP_HTTP_MAX_BODY_BYTES`, default 1 MiB; oversized requests rejected with 413 before the SDK parses the body).
  - Stricter HTTP session-init gate: stateful HTTP mode now rejects non-`initialize` requests arriving without `Mcp-Session-Id` with HTTP 400.
  - Quieter expected-client-error logging: 401/403/400/404 HTTP errors now log at `warning` level instead of triggering the full error pipeline with stack traces.
  - `GET /mcp` now includes `server.keywords` from `package.json`.
