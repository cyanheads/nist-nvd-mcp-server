# 0.1.19 — 2026-07-31

## Added

- **`nvd_get_cve_history` gains a `notice` field** — matches the enrichment `nvd_search_cves`, `nvd_search_cpes`, and `nvd_audit_cpe` already carry. An empty page now distinguishes an offset past the end of the history, an empty page inside a range NVD says has events, and a CVE NVD holds no history for; a partial page names the offset that reaches the next one, counted from the end `order` anchors to. ([#42](https://github.com/cyanheads/nist-nvd-mcp-server/issues/42))

## Changed

- **`CveRecord` has one schema declaration** — `nvd_audit_cpe`'s inline `CveRecordSchema` moved to `src/mcp-server/tools/schemas/full-cve.ts`, parallel to `brief-cve.ts`; both `nvd_audit_cpe` and `nvd_get_cve` build from it instead of drifting independently. ([#37](https://github.com/cyanheads/nist-nvd-mcp-server/issues/37))
- **`nvd_get_cve`'s advertised item schema now covers full mode, the default call, instead of describing brief-only fields** — the item schema extends the shared `CveRecordSchema` with the two brief-only fields (`description`, `cisaVulnerabilityName`), every full-record field marked optional since `brief: true` never emits them. `format()` was rewritten from a `brief`-branched pass to one pass that checks each field's presence independently. ([#38](https://github.com/cyanheads/nist-nvd-mcp-server/issues/38))
- **A parameter rejection from NVD on a CPE input now reads as a malformed CPE** — `auditCpe()` and `searchCpes()` catch `isNvdRequestRejected` and re-throw as `invalid_cpe_format` with its recovery hint, matching how a rejected CVE ID is already handled. `isNvdRequestRejected` narrows to `McpError` so the call site can read NVD's own message off it. ([#45](https://github.com/cyanheads/nist-nvd-mcp-server/issues/45))

## Fixed

- **`nvd_get_cve_history` misreported an unrevised CVE when paging past the end under `order: "oldest"`** — `cvehistory/2.0` reports `totalResults: 0` for a `startIndex` past the end of the history, unlike `cves/2.0` and `cpes/2.0`, which keep the true count from any index. An empty page past offset 0 now re-probes at `startIndex 0` to recover the real count before deciding which notice applies. ([#42](https://github.com/cyanheads/nist-nvd-mcp-server/issues/42))
