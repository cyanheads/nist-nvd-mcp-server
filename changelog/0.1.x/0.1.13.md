# 0.1.13 — 2026-07-15

## Added

- **`configurations[].operator`** — the group-level AND/OR combining sibling nodes is now typed on `RawCveItem` and `CveRecord`, carried through `normalizeCve()`, and declared on `nvd_audit_cpe`'s `CveRecordSchema`, so it reaches `structuredContent` as well as the rendered text. NVD uses it to mark jointly-required nodes — a firmware match plus the hardware it runs on — which read as unrelated alternatives while it was dropped. ([#22](https://github.com/cyanheads/nist-nvd-mcp-server/issues/22))
- **`.github/SECURITY.md`** — private vulnerability reporting policy.
- **`.gitattributes`** — LF normalization, binary-asset protection, and `linguist-generated` on `bun.lock`, `CHANGELOG.md`, and `docs/tree.md`.
- **Socket install scanning** — `bunfig.toml` registers `@socketsecurity/bun-security-scanner` under `[install.security]`, scanning every package before install. Configuring a scanner disables Bun's auto-install.
- **`minimumReleaseAge` supply-chain guard** — `bunfig.toml` blocks package versions published less than 3 days ago, excluding `@cyanheads/mcp-ts-core`. `scripts/devcheck.ts`'s outdated check now skips rows bun marks `*` (held by the gate, nothing to adopt) while still failing on a genuine update.

## Changed

- **Docker base images pinned** — `oven/bun:1.3` → `oven/bun:1.3.14` on both stages; BuildKit cache mounts persist Bun's package cache across builds, and the build stage installs with `--ignore-scripts`.
- **`devcheck.config.json`** — `outdated.allowlist` holds `typescript` at `^6.0.3` (7.0.2 is out).
- **`package.json`** — `author` is now `Casey Hand <casey@caseyjhand.com> (https://caseyjhand.com)`; `packageManager` `bun@1.3.2` → `bun@1.3.14`; `engines.bun` `>=1.3.2` → `>=1.3.0`.
- **`changelog/template.md`, `scripts/build-changelog.ts`** — the `security:` frontmatter flag is documented as a source-code signal; a dependency or transitive CVE bump records under `## Dependencies` and leaves the flag `false`.
- **LICENSE** — copyright year 2025 → 2026.

## Fixed

- **Retries no longer burst inside one rate-limiter slot** — `NvdHttpClient.get()` composes `withRetry(() => schedule(fetchOnce))`, so every attempt is enqueued separately and waits out the inter-request gap instead of firing up to 4 unpaced requests against NVD's 5-per-30s keyless budget. ([#21](https://github.com/cyanheads/nist-nvd-mcp-server/issues/21))
- **A 403 now holds the whole queue** — the parsed `Retry-After`, clamped to the 30s window, sets a `backoffUntil` that stops every pending request from firing into a window that is already closed. A keyed call spends one patient retry across it; a keyless call fails fast naming `NVD_API_KEY`, and drops to `maxRetries: 1` for other transient failures. ([#21](https://github.com/cyanheads/nist-nvd-mcp-server/issues/21))
- **Deterministic rejections fail fast** — NVD's parameter-rejection 404 is now an `McpError` carrying `data.retryable === false`, so `withRetry` stops re-sending a request that cannot succeed. `fetchById()` and `getCveHistory()` key off it via the exported `isNvdRequestRejected()` guard rather than an `'HTTP 404'` message substring. ([#21](https://github.com/cyanheads/nist-nvd-mcp-server/issues/21))
- **A refused API key is no longer reported as a malformed CVE ID** — NVD answers both faults with 404, separated only by a `message` response header; a refused key now raises `ConfigurationError` / `nvd_invalid_api_key` naming `NVD_API_KEY`. ([#21](https://github.com/cyanheads/nist-nvd-mcp-server/issues/21))
- **`nvd_audit_cpe` printed bare `Operator:` lines carrying no CPE data** — the Configurations block now renders one line per CPE match (criteria string, version bounds, node and group operators, and a marker when the CPE is context rather than the vulnerable component), capped at the first 5 per CVE with a `… N more` trailer, matching the `references` cap in the same formatter. ([#22](https://github.com/cyanheads/nist-nvd-mcp-server/issues/22))
