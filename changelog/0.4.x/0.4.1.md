# 0.4.1 — 2026-11-15

## Added

- **CNA/ADP record fields** on `nvd_get_cve`, `nvd_audit_cpe`, and `nvd://cve/{cveId}`: `affectedProducts` (with `versionChanges`), `cveTags`, `cvssScores[].source`, and `sourceIdentifier`. `includeAffected: false` omits `affectedProducts`. [#65](https://github.com/cyanheads/nist-nvd-mcp-server/issues/65)
- **KEV-addition window** on `nvd_search_cves`: `kevDays` or `kevStartDate`/`kevEndDate` select CVEs CISA added to KEV in the span. [#66](https://github.com/cyanheads/nist-nvd-mcp-server/issues/66)
- **`nvd_audit_cpe` server-side filters:** `kevOnly`, `severity`/`severityVersion`, and publication, last-modified, and KEV-addition windows, with `filtersApplied` and `datesClamped`; a filtered zero result reads as no match for the filters, not a clean audit. The audit declares the same date-window reasons and `invalid_severity_for_version` as `nvd_search_cves`, raised before any request. [#68](https://github.com/cyanheads/nist-nvd-mcp-server/issues/68)
- **`nvd_get_cve` `cveIds` string** is split on commas and whitespace, handled exactly as the array form. With `NVD_CLAMP_LIMITS=false`, a string naming more than 100 distinct IDs fails the newly declared `too_many_cve_ids` before any request. [#71](https://github.com/cyanheads/nist-nvd-mcp-server/issues/71)

## Changed

- **`cvssScores[].sourceType` description** says it is NVD's Primary/Secondary label, not the scorer; `source` names the scorer. [#65](https://github.com/cyanheads/nist-nvd-mcp-server/issues/65)
- **`nvd_invalid_api_key`** is declared on every tool and the CVE resource; API-key hints and `rate_limited` recoveries are worded as server-operator settings, and `NVD_REQUEST_TIMEOUT_MS` is documented as the per-attempt timeout. [#72](https://github.com/cyanheads/nist-nvd-mcp-server/issues/72)

## Fixed

- **Shorthand-window paging:** the first page's next-page notice names the `filtersApplied` dates to send instead of `pubDays`, `lastModDays`, or `kevDays`. Past offset 0 the notice names only the offset, and a separate notice says the window re-expanded and the first page's dates hold it still. [#67](https://github.com/cyanheads/nist-nvd-mcp-server/issues/67)
- **Shorthand expansion** is exactly N × 24 h in UTC; a window across a clock change no longer shifts by an hour or exceeds 120 days.
- **`severityMin` emptied page:** `nvd_audit_cpe` names the next offset, or says the target is exhausted at that threshold. [#69](https://github.com/cyanheads/nist-nvd-mcp-server/issues/69)
- **Source dictionary load** makes one 20 s attempt capped by the call deadline; a deadline-cut load leaves the cache as it was, and a waiting call follows its own deadline and cancellation. [#70](https://github.com/cyanheads/nist-nvd-mcp-server/issues/70)
- **One 55 s deadline** covers every NVD request a call makes. A request that outlives its timeout, or a call that runs out the deadline, fails `nvd_timeout`; an NVD 5xx or network failure that outlasts the client's retries fails `nvd_unavailable`. Both are retryable and declared on every tool and the CVE resource. [#72](https://github.com/cyanheads/nist-nvd-mcp-server/issues/72)
- **Explicit dates** must match `YYYY-MM-DDThh:mm[:ss[.fraction]][Z|±hh:mm]` or fail `invalid_date_format` before any request; a date alone, a space separator, a colonless offset, an offset past ±18:00, and a fraction past nine digits are rejected. [#71](https://github.com/cyanheads/nist-nvd-mcp-server/issues/71)
- **CPE rejections:** an NVD 404 that does not name `cpeName` or `virtualMatchString` is `nvd_request_rejected`, no longer `invalid_cpe_format`; `nvd_search_cpes` applies the same rule to `cpeMatchString`, and both tools now declare `nvd_request_rejected`. [#68](https://github.com/cyanheads/nist-nvd-mcp-server/issues/68)
- **Keyword too broad:** on `nvd_search_cves`, NVD's rejection carries recovery that points at the keyword.
- **`nvd_get_cve` ID cap** deduplicates IDs case-insensitively before counting to 100.
